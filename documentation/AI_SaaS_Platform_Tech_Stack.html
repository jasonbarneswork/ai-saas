What We're Deliberately NOT Using

One of the architectural decisions shown in the source material is not using Laravel.

Instead, the application is built around a lightweight stack:

PHP 8.4 + Slim 4 + Custom Controllers + Repositories + Validation + Middleware + Resources + Docker
Why this approach?
The source material describes the application as lightweight and intended to give a clearer understanding of what is happening underneath the framework.

Architecture Summary

Layered REST API using middleware, controllers, repositories, validation, resources, PostgreSQL, and Dockerized infrastructure.

Ownership Authorization

User 2 | ├── Can update listing 3 ✓ ├── Can delete listing 3 ✓ └── Cannot update listing 1 ✕
Ownership checks ensure that a user can modify the listings they own while preventing updates to another user's listing.
